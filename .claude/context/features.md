## 1. Accounts and pairing

**Status:** Built

**What it does:** Signs a person in with a six-digit email code, asks for their name, and pairs them with their partner. Once paired, the app opens on the Calling / Notes / Hobbies tab shell with the partner's name on the Calling tab.

**Flow:**
1. Email screen: type an email, "Send code". Supabase emails a six-digit code (locally caught by Mailpit at `http://127.0.0.1:54324`).
2. Code screen: type the code, "Sign in". A wrong or expired code shows "That code didn't work." and stays on the screen.
3. Name screen: type a name, "Continue". Saves `profiles.display_name` and `profiles.time_zone` (from the phone).
4. Pair screen: an invite is created on arrival; "Invite" opens the share sheet with `buttercup://invite/CODE` and "Pair with me on buttercup", and the code is shown as selectable text. The partner opens the link or pastes the code and taps "Pair", which calls `accept_invite`. The inviter's screen refreshes every 5 s and on becoming active, so it moves on once the partner accepts.
5. Ready: each phone sets its own `avatar_tint` to the first NotePaper colour (Blue, Pink, Green, Lilac, Yellow) the partner isn't using; on a collision the later-created profile moves on next launch.
6. Sign out: Settings → Account "Sign out" (and the Pair screen) returns to the email screen.

**Rules:**
- State: no session → email; empty `display_name` → name; no partner profile visible → pair; otherwise the tab shell. The partner's `profiles` row is only readable once paired (RLS), so its presence decides paired vs unpaired.
- A `buttercup://invite/CODE` link opened while signed out or before the name is set is kept in memory and accepted once the app reaches the Pair screen. Links opened while already paired are ignored.
- Invite errors: `invite_not_found` "That code isn't right.", `invite_expired` "That invite has expired. Ask for a new one.", `invite_used` "That invite was already used.", `cannot_pair_self` "That's your own invite.", `already_paired` "You're already paired."
- Session is stored by `supabase-swift` in the Keychain (`kSecAttrAccessibleAfterFirstUnlock`) and survives relaunch.
- Offline launch: after each successful `refresh()`, `me`, `partner` and `pairedAt` are saved as JSON under `session` in the App Group `UserDefaults` (`group.com.adamfilchoir.buttercup`). Sign-in shows only when no session is stored (or the server rejects it); if refreshing the token or loading `profiles` fails with a network error on launch, the saved copy restores the same screen (tabs, name or pair). With a stored session but no saved copy, the root shows "Couldn't connect" with a "Try again" button. It retries on becoming active and when `NWPathMonitor` reports a connection. Sign out clears the saved copy.
- Debug builds talk to local Supabase (`http://127.0.0.1:54321`); Release builds to the hosted project. Set by the `SUPABASE_URL` / `SUPABASE_ANON_KEY` build settings, read from `Info.plist`.
- Failed actions play the `.error` haptic; nothing else has a haptic.

**Code:** `ButtercupKit/Sources/ButtercupKit/SessionStore.swift` (client, `Profile`, `SessionStore`), `Buttercup/Onboarding.swift` (email/code, name, pair screens), `Buttercup/SettingsView.swift` (Account → Sign out), `Buttercup/ButtercupApp.swift` (root switch, "Couldn't connect", `onOpenURL`), `ButtercupKit/Sources/ButtercupKit/Outbox.swift` (`onOnline`), `Buttercup/ContentView.swift` (`CallingTab`), `Buttercup/Info.plist` (URL scheme, Supabase keys), `supabase/config.toml` + `supabase/templates/code.html` (email code template). Spec: [prds/completed/2-foundation-sign-in-pairing.prd.md](../prds/completed/2-foundation-sign-in-pairing.prd.md).

**Known gaps:**
- Sign in with Apple is not built (needs a paid Apple Developer account).
- No unpairing.
- Screens are plain SwiftUI, not yet restyled to the design system.

## 2. Calls

**Status:** Built (partial): backend and app screens are built; simulator-to-browser media (AC1), two-device calls (AC2) and the partner-side view of a camera toggle (AC6) are not yet verified; the ARKit camera ([4]), face stickers ([5]), 3D sticker tracking ([28]) and drawing-pad stickers ([6]) are built but not yet run on a device; the in-call restyle ([29]) is built and checked on two simulators except for the face-dependent sticker steps, drag out of the panel, the keyboard layout, the route picker, accessibility settings and iOS 18. The Calling tab restyle ([30]) is built and checked on two simulators except for iOS 18.

**What it does:** Creates, answers and ends 1:1 audio and video calls between paired partners. A call is one `calls` row plus a LiveKit room named after its id; the functions return LiveKit tokens, and the apps follow status changes over Realtime.

**Flow:**
1. `start-call {kind}` finds the partner, inserts a `ringing` row with `room_name = id`, and returns `{call, token, livekit_url}`.
2. The callee's app sees the insert over Realtime `postgres_changes` on `calls`.
3. `answer-call {call_id}` (callee) sets `answered` + `answered_at` and returns the callee's token. Repeating it on an answered call returns a fresh token (reconnect).
4. `end-call {call_id, reason}` sets `declined` (callee, from ringing), `cancelled` / `missed` (caller, from ringing) or `ended` (either, from answered), with `ended_at`.
5. A `pg_cron` job (`sweep-ringing-calls`, every minute) marks calls still ringing after 60 s as `missed`.
6. App: the Calling tab ([30]) is a `ScrollView` on Background. The title row is "Calling" with the `doodle-flower` doodle (hidden while the empty Recent calls card shows) and today's date. The partner card has the 56 pt avatar, the name and a last-call line from the newest `calls` row ("Last call yesterday · 42 min", "Missed call today", "Last call {day}" without a duration, or "No calls yet"), and equal 56 pt Audio / Video pills (disabled at 40% unless idle and paired; stacked full width at accessibility sizes). The latest-note card shows the partner's newest note from the last 30 days as a 112 pt tile with a 3 + 3 Highlight ring and a "New" badge while its id differs from `@AppStorage("lastSeenNoteID")`; tapping the tile sets it (the ring fades over 0.15 s) and opens `NoteDialog` on that day's notes from both people. "Send one back" opens `NewNoteView` full screen and shows the same toast as the Notes tab. The card refreshes on every notes Realtime change and is hidden when there's no partner note. Recent calls is one card of rows with a 38 pt icon tile (`video` / `phone`, or `phone.down` in Danger for missed), "Video call" / "Audio call", "{Today / Yesterday / Mon 12 Oct} · {N min}", "Missed" (Danger, bold), "Declined" or "Cancelled", and the start time; when empty it is a card with the doodle, "No calls yet" and "Give {name} a ring?". Tapping a button shows "Calling {name}…" with Cancel; the callee gets a "{name} is calling" sheet with Answer and Decline.
7. App in-call screen ([29], spec `design/specs/in-call-screen.md`): always dark. The partner fills the screen; a frosted name pill at the top shows their name and the call timer (or "Connecting…" / "Reconnecting…"). Your 100 × 150 tile sits in a corner and can be dragged to any corner (it snaps to the nearest corner to the release point plus 0.15 s of velocity). Tap it for the medium tile (70% width, 2:3, 40% dim; tap the dim to shrink): Expand, Flip camera and Add stickers for you, Expand only for the partner. Expand swaps the big and small views. The bar is five frosted 56 pt circles: Stickers, Mute, Camera, Audio route (an `AVRoutePickerView` under a symbol that follows the route) and End call. Mute on and camera off fill Accent with slashed symbols; End is Danger. Camera off shows the person's avatar (128 pt with name and "Camera off" in the big view, 96 or 56 in tiles).

**Rules:**
- One active (`ringing` or `answered`) call per pair, enforced by the `calls_one_active_per_pair` index. If the partner's call is already ringing, `start-call` returns `{call, incoming: true}` and no token; repeating my own ringing call returns it again.
- An `answered` call whose LiveKit room is empty (both apps died) is ended by the next `start-call`; if someone is in the room, `start-call` returns 409 `busy`.
- Errors are `{error}`: 400 `bad_request`, 401 `unauthorized`, 403 `not_paired`, 404 `call_not_found`, 409 `busy` / `call_not_ringing` (with `status`) / `invalid_transition`. `end-call` on a finished call returns it unchanged.
- Tokens: identity = user id, 2 h TTL, join/publish/subscribe for that room only. Never stored in `calls`.
- The app only reads `calls` (RLS: caller or callee); all writes go through the functions with the service role.
- App: `end()` sends `cancelled` from outgoing, `declined` from incoming, otherwise `ended`. An unanswered outgoing call sends `missed` after 45 s. "Reconnecting…" shows when the partner leaves the room or the app's LiveKit connection drops (including quick reconnects), and the call sends `ended` if it hasn't recovered after 30 s.
- App: if both partners tap Call at once, the second `start-call` returns `incoming: true` and that phone shows the incoming sheet.
- App: on the simulator the camera is a looping test clip (`TestClipCapturer` into a `BufferCapturer`); Flip does nothing there.
- App: on a device the front camera is ARKit face tracking (`ARKitFaceTracker`: 1280×720 @ 30 fps, light estimation off, one face), with each `ARFrame.capturedImage` pushed into a `BufferCapturer` rotated 90°. The back camera is LiveKit's camera capturer. Camera off and Flip unpublish the video track and pause ARKit, and Camera on or Flip publishes a new track from the chosen source. The self preview is mirrored for the front camera: with ARKit or the clip it is its own composite from `StickerCompositor` (mirrored video, shown through an `AVSampleBufferDisplayLayer`); with LiveKit's capturer it is LiveKit's mirrored view. Thermal state is logged on each change.
- App: face stickers ([5], restyled in [29]). Stickers in the bar, or Add stickers on your medium tile, opens the effects panel: drawn inside the call view (not a sheet), 50% of the screen tall, following the system light or dark scheme, covering the bar, with the partner's tile moved to the top corner on its side. It has ✕, a grabber and pill tabs Stickers · Emoji · Text · Draw and closes on ✕, a swipe down on its header (past 30% or fast) or the escape gesture. It reopens on the last tab used in the app session (Stickers first). With your front camera on, opening it from the partner-big state swaps your view big first; with the camera off or flipped it stays put and every tab is at 40% with "Stickers come back when your camera's on". Stickers is a 3-row grid of every PNG in `assets/stickers` (bundled as the `stickers` folder; "No stickers yet." when empty) with "Drag one onto your face". Emoji is Apple's full set (bundled `Resources/emoji.json`, filtered to what the device renders) in a 3-row strip with category labels and nine jump chips; long-press opens the skin-tone picker and the pick is remembered per emoji. Text is a field (30 characters), Add, six colour dots (Ink, Buttercup, Pink, Blue, Green, Lilac) and a checkerboard preview drawn like the sticker; the panel shrinks to 292 pt while the field has focus. Draw ([6]) turns the panel into the pad in place, as in the in-call mockup: the header becomes ✕ · "Draw" · ✓ (Accent, 40% until a stroke), and below it `DrawingPad` is a `PKCanvasView` on the checkerboard (radius 20, 2 pt Outline, "Draw something to wear" until the first stroke) that ends 12 pt above Apple's `PKToolPicker` (shown as the canvas becomes first responder, light-mode colours; its frame is re-measured 0.4 s after it appears because it reports zero height while sliding in). ✕, a swipe down on the header or the escape gesture discards the drawing and goes back to the tab used before Draw; ✓ renders `drawing.image(from: drawing.bounds, scale: 2)` in light mode once into a `CIImage`, so only the strokes are kept on a transparent background, and adds it as a `.drawing` sticker exactly like a tapped emoji. Drawings are not saved between calls. Tapping a cell or Add places the sticker at the nose point, selected, and closes the panel. Dragging a cell up out of the panel hides the panel once the finger is above its top edge and brings it back if the finger goes back below; a drop above the edge places it where the finger lets go and closes the panel. A drop inside a camera-facing `ARFaceGeometry` triangle pins to that spot on the skin (triangle plus barycentric weights) and turns with it; a drop anywhere else pins to a head-fixed plane through the nose tip, with no distance limit ([28]). Each sticker is a 6 cm quad (× its scale) in face space, upright to the head, projected each frame and drawn in perspective with `CIPerspectiveTransform`, so it tilts, turns, foreshortens and scales with distance; one facing away from the camera is not drawn. In the big self view: drag moves and re-pins, pinch resizes (0.3–5×), twist rotates, tap selects (an Accent rounded outline 8 pt outside the sticker's projected quad, in the preview only) and shows a 56 pt frosted trash 16 pt above the bar; selecting closes the panel. VoiceOver exposes each placed sticker with Remove, Make bigger and Make smaller actions. Placing plays `.impact(weight: .light)`. Max 10, after which the panel's cells, Text and the pad are disabled with "That's 10. Remove one to add more." At thermal `.critical` they are disabled with "Stickers are paused while your phone cools down." While no face is tracked, they are disabled at 40% with "Show your face to add stickers" and nothing can be placed. `StickerCompositor` draws them with Core Image (one Metal `CIContext`, one BGRA `CVPixelBufferPool`, each sticker pre-rendered once) between the frame source and `BufferCapturer`, so the partner sees them unmirrored; with no stickers or at thermal `.critical` the raw frame is sent. It renders a second, mirrored buffer for your own tile with each sticker's corners swapped so text and images read the right way round. A frame without a tracked face draws no stickers (they return with the face). Frame time for both renders is logged every 30 frames. Stickers survive camera off/on and are cleared when the call goes idle. The back camera has no stickers.
- Local LiveKit is `livekit-server --dev --bind 0.0.0.0` (`devkey` / `secret`). Functions reach it at `LIVEKIT_API_URL` (`http://host.docker.internal:7880`); apps use `LIVEKIT_URL` (`ws://127.0.0.1:7880`).

**Code:** `supabase/functions/start-call/index.ts`, `supabase/functions/answer-call/index.ts`, `supabase/functions/end-call/index.ts`, `supabase/functions/_shared/supabase.ts` (admin client, auth, `loadCall`, `transition`), `supabase/functions/_shared/livekit.ts` (tokens, room participant check), `supabase/functions/.env.example`, `supabase/migrations/20261020082738_calls_rules.sql` (index, sweep, cron), `supabase/functions/tests/calls.test.ts`, `supabase/tests/database/calls_rules.test.sql`, `ButtercupKit/Sources/ButtercupKit/CallStore.swift`, `ButtercupKit/Sources/ButtercupKit/Call.swift`, `Buttercup/Calling/` (Calling tab, outgoing, incoming sheet, in-call, test clip capturer, `FaceTracker.swift` ARKit face tracker), `Buttercup/ContentView.swift` (call overlay, sheet, alerts, the one `NotesStore.changes()` subscription shared by the Calling and Notes tabs), `Buttercup/DesignSystem/Doodle.swift` + `Buttercup/Assets.xcassets/doodle-flower.imageset/` (doodle), `Buttercup/ButtercupApp.swift` (`CallStore`, `resync()` on becoming active, wires the clip or the ARKit tracker through `StickerCompositor` into `CallStore`, clears stickers on idle), `Buttercup/Effects/` (`Sticker.swift` types, `EffectTab` and `StickerLayer`, `StickerCompositor.swift`, `EffectsPanel.swift`, `StickerGestures.swift`, `DrawingPad.swift`), `Buttercup/DesignSystem/` (shared `PillTabRow`, `StickerGrid`, `EmojiStrip`, `SkinTonePicker`, `TextStickerComposer` with `Checkerboard`, `ColourDots`, `IconCircleButton`), `assets/stickers/` (image stickers, folder reference in the project). ## 3. Notes

**Status:** Built (partial): the new note screen's frame, the Draw, Stickers, Emoji and Text tabs with placing and editing, Photo mode, the outbox that uploads notes, Send with its toast, the read path (`notes(in:)`, `image(for:)`, `changes()`, `pairedAt`), the Notes tab week view (strip and day grid), the month view with its toggle, and the note dialog. VoiceOver on the week view ([18] AC9), in the note dialog ([19] AC7) and on the month view ([20] AC8) hasn't been heard. The Wi-Fi offline check ([15] AC2, [16] AC4) and the send haptic and VoiceOver announcement on a device ([16] AC2, AC5) haven't been run.

**What it does:** The Notes tab shows a Monday-first week strip that pages by week from the pairing week to the current week, and the selected day's notes in a newest-first 2-column grid. A pill in the title row switches to a month calendar with a blue dot for your notes and a red dot for your partner's on each day, plus the month's totals; tapping a day opens its week. Tapping a note opens it big in a dialog over the dimmed tab that pages through that day's notes. "Make a note" on the Notes tab opens the New Note Screen as a full-screen cover. You can draw on the white canvas with a pen in 10 ink colours, erase whole strokes and undo, place stickers, emoji and typed text that you move, pinch, rotate and remove. In Photo mode you take a square photo with the camera and use every tool on top of it. Send flattens the note to a 1000 × 1000 HEIC, queues it in the outbox, closes the cover and shows a toast.

**Flow:**
1. Notes tab [18]: "Notes" (`.largeTitle` heavy) with the toggle pill trailing [20], then the full-width "Make a note" (`pencil.tip`, primary pill, 56 tall, sticker shadow) that presents `NewNoteView` with `.fullScreenCover`, then the week strip; only the day content below scrolls. On open the current week shows with today selected.
   - Strip: 7 cells (Surface, 2 pt Outline, radius 14, ~48 × 74) with the narrow weekday, the date in monospaced digits and up to 3 stacked 15 pt crops of the day's newest note images. Today is Accent with OnAccent content; the selected day has a 2.5 pt Outline ring 2 pt outside the cell. Tapping any cell (past, empty, future) selects it with a 0.15 s fade and no haptic.
   - Paging: a paging `ScrollView` with one page per week from the week containing `pairedAt` to the current week; when a swipe settles, the same weekday in the new week is selected and that week is fetched.
   - Day: header "Saturday 31" (never "Today", header trait) with "No notes", "1 note" or "N notes"; a 2-column grid (1 column at accessibility sizes) of `NoteTile`s (radius 20, 2.5 pt Outline, 24 pt sender `Avatar` with an Outline ring 8 pt in from the bottom-left), newest first. An empty day shows "No notes yet".
   - Note dialog [19]: tapping a tile opens `NoteDialog` in a `DialogCard` from a root overlay in `ContentView` (above the toast, below the call screen). The scrim is black at 42% (light) or 60% (dark) over the whole screen, tab bar included; the card is Surface, 20 pt from the edges, radius 28, 2.5 pt Outline, 16 pt padding. Header: 40 pt sender `Avatar` with a 2.5 pt Outline ring, the name ("You" or the partner's name, `.headline`) over the date and time ("Saturday, 31 Oct · 8.18" in the device locale, `.subheadline` medium, monospaced digits), and a `.plain` ✕ `IconCircleButton`. Below, a full-width square note (radius 20, 2.5 pt Outline) in a horizontal paging `ScrollView` over the day's notes, newest first, opening on the tapped one; swipe left for older, right for newer, stopping at both ends. Pager: 8 pt dots, 8 pt apart, 1.5 pt Outline, current filled Outline, others Divider; hidden for a one-note day. ✕ or a scrim tap closes it; swipe down does nothing. Open: scrim fade and card fade plus 0.96 → 1 scale over 0.2 s ease-out; close: 0.15 s fade; Reduce Motion drops the scale. No haptics. On each refetch `DayGrid` updates the dialog's notes, or closes it if the open note is gone (unsent). An image that fails to load shows the tile's Divider fill and warning glyph.
   - Toggle [20]: a small secondary `PillButtonStyle` (40 visible, 44 hit, Surface, 2 pt Outline, `.subheadline` bold, 6% TextPrimary on press, no scale). Week view: `calendar` + the selected day's month (`.month(.wide)`); month view: `calendar.day.timeline.left` + "Current week". At accessibility sizes the title row stacks and the pill sits under the title. Switching cross-fades everything below "Make a note" and the pill's label over 0.18 s ease-out; nothing slides, no haptic. "October" opens the selected day's month; "Current week" returns to the current week with today selected.
   - Month view [20]: `MonthCalendar`, a paging `ScrollView` with one page per month from the month containing `pairedAt` to the current month. Each page is a Card (radius 22, 2.5 pt Outline, padding 14 / 10 / 10) with "October 2026" (`.title3` heavy), the M–S row and a Monday-first grid of 4–6 rows (cells ~48 × 52, gaps 2 / 4, no fill). Spill days are semibold TextSecondary with the cell at 50%; today is Accent with a 2 pt Outline. `DayDots` shows two fixed 8 pt places with 1.5 pt Outline rings (OnAccent on today): `NoteDotMine` left, `NoteDotPartner` right, for presence only. Under the card: "11 notes this month" / "N notes in September" / "No notes …" and the legend "● 4 from you ● 7 from Partner" (stacked at accessibility sizes), counting only the month's own days. Tapping a day whose week is within the strip's limits switches to that week with the day selected; days in weeks before pairing or after the current week are not tappable and have no button trait. Each visible month loads with one `notes(in:)` over its grid span (up to 6 weeks); a failed fetch leaves the dots empty until the next refresh. The month content scrolls vertically only if it overflows.
   - States: before the week's first fetch, a `ProgressView` appears after 1 s; a failed fetch shows "Couldn't load notes. Try again" with a small secondary "Try again" and empties the strip's mini-cards; a tile whose image fails keeps the Divider fill with `exclamationmark.triangle`.

The tab keeps its mode, month and selection across tab switches.
   - VoiceOver: the strip is one adjustable element ("Week of 26 October", value like "Saturday, 31 October, today, 4 notes"; swipe up or down changes day) with "Previous week" / "Next week" actions only within the limits; each cell is a button with the same style of label and the selected trait. Month view [20]: the toggle reads "Show month, October" or "Show current week"; each day reads like "Tuesday, 27 October, notes from Partner" ("notes from you", "notes from you and Partner", "no notes", plus "today"); the month title is a header; the title and every day carry "Previous month" / "Next month" actions only within the limits; the summary reads as one element ("11 notes this month, 4 from you, 7 from Partner"); the card caps at `.accessibility1` with the Large Content Viewer on cells.

Stickers and emoji are squares 30% of the canvas side; text is 52/398 of the side in font size, sized to its own line and shrinking to fit the canvas width, and its selection outline and trash badge follow its measured size. Items sit above the strokes in array order, newest on top. Undo never touches items.

## 4. Sounds

**Status:** Built (partial): the backend and the Sounds tab with playback ([22]); the tab bar still has Settings as a fifth tab, and playing with the silent switch on is unchecked on a device. Recording, editing and in-call sounds ([23]–[27]) aren't built.

**What it does:** Keeps one shared soundboard per pair. A sound is a short clip (up to 10 s) with a title and an optional emoji. Both partners can play, rename, re-emoji, trim, reorder and delete every sound in the pair's library.

**Flow:**
1. A new sound is one `sounds` row plus one `.m4a` file at `{sender_id}/{id}.m4a` in the private `sounds` bucket.
2. On insert, the `sounds_set_position` trigger sets `position` to the pair's minimum minus 1 (0 when the pair has none), so new sounds come first without the app knowing the order.
3. Reordering calls `reorder_sounds(ordered_ids)`, which locks the pair's rows, checks the ids are exactly the pair's sounds and rewrites `position` 1…n. Any other set raises `sounds_mismatch` and changes nothing; the last commit wins.
4. Deleting removes the row under RLS, then the file with the Storage API (no delete RPC).
5. Changes reach the partner over Realtime (`sounds` is in `supabase_realtime`); no push is sent.
6. App ([22]): the Sounds tab sits between Notes and Hobbies (`speaker.wave.2`, `.fill` when selected). It shows "Sounds" (largeTitle heavy), then a 3-column grid (2 at accessibility sizes) of 108 pt tiles with 12 pt gaps: the Accent "+ Record" tile with the sticker shadow first (drawn, no action until [23]), then the pair's sounds by `position`. A sound tile is Surface with a 2.5 pt Outline, radius 20, the emoji (🔊 when null) and the title in 2 lines. With no sounds it shows "No sounds yet. Record one for {name}?" and "Up to 10 seconds. Sounds you save show up for you both."
7. Tapping a tile plays `trim_start_ms`…`trim_end_ms` on this phone only through `AVAudioSession` `.playback`; a PlayTint fill grows from the left at the clip's pace with a stop badge, and fades out over 0.15 s at the end. Tapping the playing tile stops it; tapping another switches. A file not cached yet shows a small `ProgressView` in the badge spot (tap again cancels); if the download fails, `.error` plays and the title reads "Couldn't load. Try again" in Danger for 3 s.
8. The tab opens on the last list saved in the App Group, then refetches on appear, on becoming active and on every `sounds` Realtime change (one `SoundsStore.changes()` subscription in `ContentView`, which retries joining every 5 s if the server was unreachable). Each fetch saves the list, downloads missing files to `Sounds/{id}.m4a` and removes files whose row is gone. If the playing sound is deleted, it stops. Offline, cached sounds still play.

**Rules:**
- RLS: select, update and delete when `sender_id = auth.uid() or is_paired_with(sender_id)`; insert only as yourself. A stranger sees and changes nothing.
- Only `title`, `emoji`, `trim_start_ms` and `trim_end_ms` are updatable by the app; `position` changes only through `reorder_sounds`.
- Checks: title 1–30 characters after trimming; emoji null or 1–16 characters; `duration_ms` 1–10000; `trim_start_ms ≥ 0`; `trim_end_ms ≤ duration_ms`; `trim_end_ms − trim_start_ms ≥ 500`, or the full clip when it's under 0.5 s; `audio_path` must be `{sender_id}/{id}.m4a`.
- Bucket `sounds`: upload to your own folder; read and delete your own or your partner's folder.
- Trim is stored as `trim_start_ms` / `trim_end_ms`; the file is never rewritten.
- App: no haptics on play or stop; VoiceOver reads the title (not the emoji), hint "Double-tap to play", value "Playing" and hint "Double-tap to stop" while playing; "+ Record" reads "Record a sound". The scroll position is kept across tab switches.
- Seed data: sounds `c0000000-…-0001` to `-0006` from both people (`-0003` has no emoji, `-0004` is trimmed, `-0002` is under 0.5 s), with mono AAC files in `supabase/seed-sounds/` uploaded by `supabase/seed-sounds.sh` after `supabase db reset`.
